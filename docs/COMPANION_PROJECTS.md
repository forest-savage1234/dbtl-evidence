# Independent projects, complementary evidence

[Claim Review](https://github.com/forest-savage1234/casefile-provenance-demo/tree/main/claim-review) reconstructs declared published numerical claims from retained sources. [ME2026](https://github.com/forest-savage1234/metabolic-engineering-forensics) preserves its related research records. DBTL Evidence handles local versioned experimental comparisons and reassessment. Repositories, release histories, databases and scientific claims remain separate.

## Implemented boundary as of v1.9/v2.0

DBTL receives `claim-review/1` reports from `0.3.2-browser` with separately retained matching source bytes. The full upstream report, cell/operation specification, open/conflicting checks and limitations survive. All six receiving scientific dimensions remain open. This validates bytes and the bounded contract; it does not re-execute the producer or authenticate its authorship. A compatible code hash identifies the probe contract only.

`tools/claim_handoff_probe.cjs` executed the pinned unchanged checker core (SHA-256 `89fd6fe7ebb04640abfbe50889e75fc803e21ee8cadafbdd72c7beb67d8fb874`) to create an explicitly synthetic product/biomass example. Its source/report/provenance are under `examples/claim-review-synthetic/`. No Claim Review source or dependencies are duplicated into this project. Both tools run independently; consuming a receipt does not require Node or the checker.

Receipts are literature or synthetic reference records, never locally measured cultures. Packet references cannot increase biological n or establish transferability. Matching g/g units cannot turn biomass into consumed substrate. Claim Review's estimand, paired-estimator and physical-unit features remain proposed work in that separate project; DBTL's corresponding bounded arithmetic does not claim to upgrade the checker.

This is a one-way report/source handoff, not a browser-UI export/import round trip or a shared live database. The broader historical `decision-evidence/0.1-draft` is not an accepted importer format. See [the current workflow](V2_WORKFLOW.md) and [validation status](V2_VALIDATION.md).
