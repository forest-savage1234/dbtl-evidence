# v1.9 — separate-project evidence handoff

## Scope

The DBTL consumer accepts a Claim Review `claim-review/1`, `0.3.2-browser` report and separately transferred source bytes. Both are retained and rehashed. The receipt retains the entire upstream specification, checks, conflicts, open questions and limitations. All consumer scientific dimensions remain open. Imported literature/reference records never become local measurements or biological replicates.

## Challenges

A synthetic product/biomass report was generated by executing the pinned, unchanged Claim Review core using `tools/claim_handoff_probe.cjs`. The fixture is consumed in Python without installing Claim Review or Node. Tests challenge unknown versions/statuses, source mismatch, removed open questions, changed consumer assessments, local-origin impersonation and preservation of upstream conflict.

## Limits

This is a one-way report-and-source receipt, not a bidirectional project round trip. It does not re-execute Claim Review arithmetic or authenticate producer execution/authorship. The pinned code hash identifies the contract probe, not the author of an arbitrary report. Byte equality does not establish source authenticity, publication currency, semantic denominator validity or transfer relevance. The historical `decision-evidence/0.1-draft` remains an unimplemented broader proposal; it is not accepted by this importer. Claim Review itself is unchanged and remains independently usable.
